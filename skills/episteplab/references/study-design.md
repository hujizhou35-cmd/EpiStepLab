# 研究问题、相似研究与路线讨论

在数据来源及基本结构可行后阅读；研究目标改变时重新核对受影响部分。本文件帮助提出选择，不预先决定研究流程，也不产生从头到尾的分析代码。

## 把研究目标说清楚

逐项讨论并用普通话复述给使用者：

- 研究对象是谁，来自哪个数据库、哪些周期或波次？纳入与排除条件是什么？
- 暴露与结局分别指什么，怎么测量，单位和时间是什么？连续值、疾病诊断、量表和代理指标不要混称。
- 想回答的是现有状态的关联、未来发生风险、预测表现，还是带有因果解释的问题？明确比较对象和希望报告的效应。
- 能否支持时间顺序？横断面、重复横断面、纵向追访和死亡链接属于不同设计；多周期 NHANES 拼接通常不产生同一个人的纵向轨迹。
- 数据的调查目标、权重和覆盖范围允许把结果推广给谁？便利子样本或受限模块不自动代表全国。
- 哪些是主要问题，哪些是探索问题？使用者需要哪些可读表格、图片和交接文件？

遇到含义不明的目标，立即指出具体不确定处并追问。不要用“默认发表常用模型”代替设计决策。暴露、结局、分组界限、调整变量和分析类型要有定义依据；现有论文也可能存在偏差。

## 检索并拆解 3–5 篇最相关原始研究

围绕已讨论的问题检索，先找最近邻：相同暴露/构念、结局、数据库及设计，其次才是只相近一个部分的研究。优先查原始论文及其补充材料、研究注册或公开方案；综述用于找线索，不冒充原始研究。

至少记录检索日期、检索平台、原始检索式、实际检索范围、筛选方式和文献链接。不能把有数量上限或只查一个入口的检索写成全面系统综述，也不能把“未找到”写成“从未有人做过”。

按实际获得程度写明 `全文及补充材料`、`仅全文`、`仅摘要` 或 `无法取得`。未见正文的方法填“未核实”，不要推测。优先详细比较最相关的 3–5 篇；不足 3 篇时说明数量和检索边界，不用不相关研究凑数。

| 每篇需要拆解 | 应回答的问题 |
|---|---|
| 研究定位 | 论文题目/年份/DOI或稳定链接，原始研究还是其他文献，实际访问层级 |
| 样本 | 数据版本/周期、人群、纳排、人数及随访时间 |
| 测量 | 暴露/结局定义、字段或量表、单位、时间点、缺失和检测限处理 |
| 设计 | 横断面/纵向/预测；抽样权重、分层聚类、失访或链接资格 |
| 分析顺序 | 从提取、清洗到主要模型及附加分析，哪些步骤影响了样本 |
| 模型 | 效应量、调整变量及依据、非线性/亚组/交互、多重比较和诊断 |
| 验证与局限 | 敏感性分析、内外部验证、时间与因果限制；正文未交代之处 |
| 可借鉴性 | 本项目哪些做法可用、哪些因字段/人群/设计不同而不能照搬 |

完成后先解释这些研究的共同路线、重要分歧和本地数据约束，再提供 2–3 个真正有差别的方案。例如“先做描述与主要关联”与“在时间条件允许时做未来风险”有实质区别；不要用不同软件包伪装成不同设计。

## 共同确定研究路线

每个方案说明它回答什么、需要哪些字段、主要优点、限制和额外计算成本，并给出推荐理由。由使用者选择；把确认内容写入研究方案，待定内容单列。

研究方案至少记录：研究问题和人群、数据来源/版本、暴露与结局定义、时间关系、主要分析目标、预计步骤与交接、抽样/纵向结构、已确认决定和待决定事项。协变量选择应考虑领域知识与时间关系，区分混杂、中介及可能的碰撞变量；不要只按单因素显著性自动挑选。

路线可以列出未来步骤的名称与目的，不能据此提前生成其脚本、占位参数模型或“运行全部”入口。可选方法只在能回答具体问题且使用者选择时加入。方法越多不等于研究越好。

## 每一步讨论和确认的格式

在编写本步分析代码前，向使用者说明：

1. 本步目的、已经具备的完整输入，以及执行后产生的文件。
2. 本步需要决定的问题、合理选项、各选项影响，以及推荐理由。已有明确确认的决定直接引用，不重复索要。
3. 预期检查：样本如何变化、缺失/分组如何核对、模型诊断或图表如何验收。
4. 资源需求和本步停止位置。未知运行时间如实写未知，不能编造精确估计。

等待使用者确认当前步骤的方法与执行范围。整体路线确认只确定方向，不自动授权全部后续步骤。使用者确认的当前步骤完成后，保存代码、检查和汇报，再停在下一步的讨论处。

可直接使用的表达：

> 这一步要决定是否处理缺失值。我先列出缺失比例和缺失发生在哪些人中。完整病例分析容易理解，但可能损失样本；多重插补保留更多信息，需要合理的缺失假设和额外诊断。建议结合这些检查选择，并考虑用另一种处理方式做敏感性分析。确认后我只编写和运行这一部分。

## 修订、接续和结论边界

- 本步内的语法、路径和保存格式问题可自行修复并记录。改变样本、定义、调整变量、模型或统计方法属于研究决定，立即讨论，不为得到显著结果替换方案。
- 数据或上游代码改变时，指出哪些后续结果需复核；不自动重跑、覆盖全部下游。保留变更理由和版本。
- 接续时读取研究方案、进度记录和本步说明，核对实际输入、脚本与结果。状态文字不能替代文件检查；确认完成与当前待决事项后接着推进。
- 技术运行成功、结果稳定、科学解释成立和真实研究验收分别报告。横断面关联、预测贡献、SHAP 重要性、交互或中介估计不能自动证明机制。
- 第一版不支持 MR。BKMR 或其他可能长期运行/需要服务器的方法，按 [分析决策参考](analysis-decisions.md) 先准备代码及资源说明，等待专项执行决定。
