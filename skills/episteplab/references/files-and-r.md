# 文件组织与可手动运行的 R

## 研究目录与单步目录

研究根目录放研究方案、研究进度、必要的来源说明。编号步骤按实际研究路线增补，不规定 13 步、18 步或强制方法顺序。

下面只是**当前一步**的摆放例子，不代表提前创建整套分析：

```text
03_变量清洗/
  运行.R
  本步工具.R              # 需要辅助检查时才复制
  输入_提取数据.csv        # 完整本步输入，不是几行示例
  输入_字段说明.csv        # 需要时保存；含编码/单位/特殊缺失
  输入文件校验.csv
  输出_清洗数据.csv
  输出_人数变化.csv
  本步说明.md
  检查记录.md
  运行日志.txt
  运行环境.txt
```

输入、输出前缀可换成有意义的中文名称，只要能区分。一个入口可以按说明调用本目录内多个短 R。少量分支继续平铺，用方法/样本后缀避免覆盖；复杂分支才增设子目录。不要强制“代码/输入/输出/检查”四层目录。

## 完整输入与文件交接

- 把当前步运行真正需要的完整数据、模型对象和辅助文件放在本步。通常复制上一步清洗结果，不反复复制整个原始数据库。
- 首步准备实际会读取的原始文件和字典；未使用的数 GB 原始模块不为“齐全”而复制。
- 记录来源路径/来源步骤、源文件名、本步文件名、校验值、校验算法及复制时间。未改内容的复制应核对校验相同；base R 的 MD5 可用于普通变更检测，不是安全保证。
- CSV 方便人工查看；需要保留因子水平、标签、日期、插补集或模型时同时/改用 RDS，并附人能读的变量/结果说明。明确空字符串、NA 和特殊缺失的编码，不能因来回导出丢掉含义。
- 上游有未知手工改表、同名不同版本或缺少生成脚本，先核实，不自行补成“可复现”。
- 过大或受限制的完整输入不能自行改成路径引用。说明原因、可行方案和独立运行的影响，让使用者决定；这不是默认豁免。
- 不在运行时悄悄读取前一步目录来弥补漏复制。一个单步目录复制到另一个位置后，应能加载自己的文件。

## R 脚本的写法

开头用中文写目的、输入、输出、依赖包与已确认方案。集中列出路径、变量名、分类界限、调整集、随机种子与计算设置。

- `# 【需修改】`：只有确实需要使用者修改的路径/环境项才用。
- `# 【已确认】`：写明研究参数值、研究依据和使用者确认出处；不能只写一个没有依据的标签。
- `# 【可修改】`：颜色、字号、文件名等展示项。会影响模型或样本的参数不放在这类。
- `# 【待讨论】`：表示阻止执行的未决问题。不能赋一个临时数值并继续跑。

模板中的待填位置是待实现骨架，不是交付的正式分析。生成本步时消除研究占位项；每段代码讲清做什么、为什么、怎样检查。优先按列名操作，避免按数字选列、过多封装、跨项目 `source()` 和课程示例串接。

## 人工与命令行运行

正式入口支持 `Rscript --vanilla 运行.R`，并说明 RStudio 的打开/运行方式。可靠确定本脚本位置后使用本目录相对路径；不能确定位置时清楚提示切换到本步目录，不猜项目路径。辅助 R、配置与模型都随本步保存。

新会话不恢复 `.RData`，不自动保存整个工作区。无需 `.Rprofile` 或全局设置。用已安装包优先；缺包时说明和在允许范围内准备项目级依赖，不静默升级全局包。记录 R、包版本、种子和运行命令。临时目录/缓存/项目库均留在使用者允许的写入范围，启动 R 前设置相应临时环境；不要以全局配置修改来实现。

骨架的停止检查不是权限系统；真正确认来自对话。高计算量步骤不得以更改“已确认”变量自行启动。

## 保存前后的检查

根据本步实际操作选择检查，不对每个步骤机械套用所有检查：

| 环节 | 需要发现的具体问题 |
| --- | --- |
| 身份 | 当前数据库/周期、暴露、结局、单位是否与确认方案一致 |
| 读取 | 文件存在、必需字段及类型；本步输入校验；无隐藏外部依赖 |
| 合并 | 正确键与层级、一对一/多对一约定、键缺失/重复、未匹配来源和人数守恒 |
| 清洗 | 特殊缺失未变阴性；排除/保留人数；不合理转换和标签丢失 |
| 建模 | 实际模型样本、参考水平、调整集、权重/设计、收敛/秩/可估计性 |
| 导出 | 保存的表是否来自当前模型；OR/HR/系数尺度和区间、P值是否一致 |
| 图表 | 从正式结果对象取数；轴、分组、图例、区间、文字是否与结果对应 |
| 复跑 | 在新进程读本步输入成功；移动本步文件夹后仍可运行 |

保存模型和正式数值表后读回核对。图的底层数值表应保存，但数值一致不能替代看图；打开实际 PNG/PDF/TIFF 或渲染的表格检查裁切、遮挡、缺项和标签。没有查看能力时明确标记视觉未核对。

失败时保留日志和原因。旧输出不能冒充本次成功结果；重跑前将旧结果作为历史保留，避免默认覆盖。主结果、敏感性结果、模拟例子和未估计项清楚标记。检查通过后更新进度，汇报并停等。
