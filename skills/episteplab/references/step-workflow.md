# 逐步推进与接续

## 先确定目前在哪一步

读研究方案、研究进度、当前步说明及检查记录，并核对实际文件。使用者当前指令优先；状态文档是记忆辅助，不是可以自我批准的权限来源。

没有进度文件时，先盘点再补记录，不重建虚构历史。旧文件可以记录为“已有，来源未核实”或“已有，未复跑”。缺少输入、脚本或手工处理说明时明确指出缺口。

## 一步内的状态

使用简单中文状态即可，无需数据库或专用服务：

| 状态 | 可以做什么 | 不能据此推断什么 |
| --- | --- | --- |
| 待讨论 | 核实资料、解释选项、追问 | 不能写好全步代码后当作已确认 |
| 本步已确认 | 保存使用者原话与所选方案，写当前步代码 | 不能扩展到后面几步 |
| 代码已审查 | 运行已确认的普通步骤 | 不是结果通过 |
| 代码就绪，待决定运行 | 交付高计算量步骤及资源说明 | 不能开始计算或服务器部署 |
| 运行中/检查中 | 修复本步技术问题、复核本步产物 | 不能改变研究决定或开始下一步 |
| 本步已核对，待使用者反馈 | 汇报、回答问题、等待 | 不能自认使用者已验收 |
| 需讨论修订 | 陈述发现与选择，保留失败记录 | 不自动换方法、删变量或排样本 |
| 需重查 | 查明上游变化及受影响的结果 | 不自动覆盖/重跑已有步骤 |

不需要强迫使用者说固定口令。明确的自然语言选择即可，但“研究路线可以”“先按这个总体计划来”不能替代当前步骤中的未决选项。已经明确选择的本步，不重复索取同一确认。

## 本步讨论的最小内容

讲清“要回答什么、读哪些输入、怎样做、有哪些选择、如何检查”。复杂问题可以分几轮讨论；已确认的参数不用重新问。多选项问题应说明具体影响，不用模糊的“最优方法”替代解释。

例如插补不能只问“PMM 还是随机森林”：先讨论是否需要插补、主要变量缺失是否可解释，再讨论适用方法与结果汇总，提醒是否安排敏感性分析。亚组先讨论临床/研究依据、分层变量与界限，再讨论交互及比较数量。

获确认后只实现本步。与本步无关的源代码、下游脚本或一键生成器不提前创建。研究路线中可以列下一步名称和待决问题，不包含待确认分析的完整代码。

## 运行与修改

代码先保存再审查。普通步骤可以运行与修正到完成，但每次实质性改变都说明：

- 技术修复：纠正变量拼写、路径、保存方式等，在原方法下重查即可。
- 研究改变：排除人群、重新定义疾病、改插补、改调整集、改权重或模型、修改拆分与评价方式，立即问使用者。
- 模型失败：保存条件、错误和无法估计项；不得临时改研究设定以取得数字。
- 高计算量：先保存代码与资源报告，等待对本次运行的明确决定。估计没有依据就说不能可靠估计，不编造耗时。

不能用修改布尔变量、伪造用户引用、模拟同意或恢复旧进度，代替真实讨论。测试中的模拟对话必须标为测试，不能迁移成真实研究的授权。

## 汇报后停等

本步结束时包含：做了什么；输入与分析人数/缺失怎样变化；真实结果文件位置；数值、技术和视觉检查状态；未解决问题；下一步建议讨论的决定。技术完成和科学解释分开。

使用者反馈若仅要求调整图片，完成该调整并重查，不据此进入新研究步骤。若明确给出下一步选择，则按新选择开展；若只说“继续”但下一步仍有影响研究的选项，先问这些选项。

## 上游变更与中断恢复

在进度记录中用“依赖步骤/输入来源”描述交接。输入或代码校验值不同，标记本步与依赖它的下游需要重查，不能把旧图继续当新结果。保留旧版本，说明变更原因和计划重查范围，等待相应步骤决定。

恢复时核对：当前指令；最近使用者确认；已保存的代码；上次运行与检查证据；输入是否改变；是否已经汇报停等。未确定状态时先澄清，不重新跑全部项目。
