# 每次启动或接续时的最新方法检索

EpiStepLab v1.1.0。每次开始使用或中断后接续研究时执行，不能以技能自带的方法列表或上次记忆替代实时检索。同一会话内当前步骤的技术修复可以引用本次检索；再次接续须更新。检索得到候选方法，不直接授权分析。

## 先读取主题与已有记录

先看工作目录、研究方案、指标证据、进度和最近一次检索。确认研究人群、暴露/结局构念、主要目的、时间关系和数据结构；主题不清楚立即问最必要的问题，再开展针对主题的搜索。没有数据时仍优先解决来源，不能为了搜索方法假定字段已经齐全。

本次明确写出要调查的几个问题，例如“有没有更合适的单调关联推断”“混合类型指标是否适合降维”“本调查结构能否支持稳定分群”。不要把“前沿”“顶刊”作为唯一检索词。

## 实际搜索的三条线

1. **主题研究与应用。** 查相同或相近构念、结局、设计和数据库的原始研究及补充资料。优先详细拆解最相关的 3–5 篇，不足如实写数量和范围；不是每个方法都硬凑 5 篇。综述用于发现原始来源。
2. **方法与验证。** 查候选方法的原始方法论文、近期改进/比较/验证、限制与修订。初次默认检索实际访问日往前约三年，明确起止日期，同时不限年份追溯基础方法。近期研究不自动比成熟方案更适合。
3. **作者实现与软件。** 从原始论文、作者主页或软件官方站点确认 GitHub 仓库的对应关系，检查 README、方法文档、示例、依赖、许可、release/tag、提交记录、已知问题和可复现性；核对正式软件手册。没有 GitHub 实现或无法确认作者关系时如实写明，不能用相似仓库补成“官方代码”。发现阶段只读核查，不自行运行下载的仓库脚本、安装脚本或示例来证明方法可用。

PubMed 可结合主题同义词、方法词与日期字段，记录原始输入和可取得的 Search Details；不同平台采用各自语法，不把一套检索式原样套所有入口。基础检索与近年检索分开留痕，检索结果上的出版日、电子出版日和入库日可能不同。[PubMed 官方帮助](https://pubmed.ncbi.nlm.nih.gov/help/)

接续研究时，以最近检索记录为起点增量检查：新论文、可能延迟入库的相关材料、勘误/撤稿、已采用方法的文档修订和仓库/软件版本变化。必要时保留时间交叠，不能机械按一个出版日切断；若上次检索没有日期、范围或可靠记录，执行新的有界初次检索。每次记录本次实际查到什么，即使没有发现需要调整的进展。

## 保存能够复核的记录

使用技能附带的检索/方法比较模板或等价简明文件，至少记录：

| 类别 | 最少需要留下的信息 |
|---|---|
| 检索过程 | 日期、平台、原始查询、日期/语言/类型范围、排序和筛选方式、实际访问范围；平台返回多少、真正检查多少分别写，没有可靠总数写未知 |
| 文献 | 题目、作者/年份、PMID、DOI或其他稳定标识、原文与补充材料链接、出版日期与更新日期（如有）、本次访问日期、预印本/同行评议及勘误/撤稿状态、具体方法所在页/节/表；未查清的状态如实标记 |
| 获取程度 | 全文及补充材料、仅全文、仅摘要、仅元数据或无法获取；未读到的设定标“未核实” |
| 软件/仓库 | 项目网址、为何确认其来源、包/软件版本、release/tag及可取得的提交 SHA、发布/更新日期与本次访问日期、许可证、方法对应文件/文档及重要已知问题 |
| 评价 | 适用目标、数据及设计要求、假设、验证证据、增益、成本、推荐/不推荐理由、未决问题及使用者确认状态 |
| 接续 | 上次记录位置、此次时间范围、变化摘要、哪些既有决定可能受影响；是否需要讨论修订 |

GitHub 默认分支内容会变化，引用关键实现时尽量保存提交 SHA 对应的永久链接；tag、release 名称和实际提交能取得时一并记。取得不到版本或 SHA 写未取得，不能填“latest”伪装可复现版本。版本记录办法参见 [GitHub 永久文件链接](https://docs.github.com/en/repositories/working-with-files/using-files/getting-permanent-links-to-files) 与 [release 说明](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)。仓库的 `CITATION.cff` 可帮助发现作者希望引用的论文或软件版本，但仍要核对实际使用对象。[GitHub citation 文件说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-citation-files)

保存实际检索和访问证据；只打开技能自带的链接或软件首页，不算完成某研究主题的最新搜索。搜索摘要、AI 总结和第三方教程只能当线索，重要方法细节回到原始论文及作者/官方文档。不为留痕违规获取或重新分发受限全文。

## 怎样提出方法建议

按 [方法选择](method-selection.md) 比较能回答同一问题的成熟方案与新方案，写明新方法实际增加了什么、是否改变估计目标、是否有适用人群和设计的验证，以及本地实现能否被人理解和重跑。顶刊地位、GitHub 星标、模型复杂程度和最新发表日期不替代评价。

允许结论是“当前简单方案足够”“新方法有价值但此数据不支持”“尚无足够证据”“作为探索备选”。不承诺检索到了全世界最优秀的方法，不把有界检索写成系统综述，不把未找到写成无人做过。

先向作者用普通话说明选择、影响和推荐理由，再确认研究路线；当前步骤另行确认后才写和运行其代码。新的文献不能自动推翻冻结定义、替换模型或重跑下游。预先区分主要、次要和探索分析及多重比较范围，不能因不显著而不断扩展方法。

## 无法联网、材料不全或实现不可用

- 网络失败时保留实际失败时间、入口与原因，说明本次最新检索未完成。可以做适度重试和其他合法入口核查，不能将旧记录改成今日已检索。
- 正文/补充材料/关键软件说明缺失时标出不能核实的具体点；立即讨论由使用者提供材料、稍后再查，还是在明确限制下暂按已有证据推进。未确认前不执行依赖未知定义或方法参数的分析。
- 没有已核实的普通 R 实现、实现停更、依赖无法满足或资源不明时，说明实现、复现、依赖与资源的实际缺口，提供有依据的选择，如寻找可靠 R 实现、另议已验证方法，或由作者决定是否接受其他语言的交付。不能悄悄换语言/算法/远程环境，也不能调用未经核实的包装函数冒充已经复现原方法。
- MR 不进入建议或代码流程；高资源方法仍先交付准备材料和资源说明，等待专项执行决定，不以小样本或少迭代试跑绕过边界。

本参考所引检索/软件官方说明核查日期：2026-10-17。它们用于指导怎样检索，不是替研究主题完成了实时方法调查。
