# EpiStepLab

像人工做研究一样推进：每一步先讨论，确认后再写代码、运行和检查。交付的是人能查看、修改、重跑的研究过程。

## 不可省略的工作方式

- 只生成和执行**当前已经讨论确认的一步**。认可整体路线不等于确认所有步骤；不要提前写后续代码，也不要提供全流程运行器。
- 使用者没有明确本步选择时，讲清可选方案、影响和建议，立即追问并等待。可以继续不依赖该选择的资料核查，不得替其决定研究参数。
- 本步获确认后，可以自行修复语法、路径和导出等技术问题，直到本步检查完成。涉及样本、定义、插补、模型、调整集或方法变更，回到讨论，不悄悄替换。
- 每步带齐**实际需要的完整输入数据集**，通常是上一步清洗后的较小文件；路径清单不能代替输入。无法复制或存在数据使用限制时先说明并讨论。
- 主要用普通 R 代码，中文分段注释。正式入口必须在新 R 会话中独立运行；不依赖旧内存、隐藏 `.RData`、技能安装路径或另一个项目的脚本。
- 保存代码后再审查、运行；检查人数、数值和实际表图。文件生成或进程退出成功，不等于本步已验收。
- 本步汇报后停下，等待下一步讨论。中断后依文件和使用者原话恢复，不把状态文件或 AI 自写的“已确认”当作新的授权。
- MR 不纳入本技能。BKMR 以及其他可能需要长时间或服务器的分析，先写当前步代码和运行说明、说明资源需求，**先不执行**；不得用试跑、缩小规模或租服务器绕过讨论。

## 进入项目

先读 [数据与字段核查](references/database-audit.md) 和 [逐步推进与接续](references/step-workflow.md)。

1. 确定当前研究目录与允许写入范围，检查现有数据、字典、说明和分析。参考材料只读；不把参考项目的路径写进新脚本。
2. 数据不存在或来源不清，立即讨论：由使用者准备本地数据、指定已有路径，还是采用经核实可用的在线环境。未解决前不开始正式提取或建模。
3. 对照实际文件和官方版本资料理解数据库。先了解表结构，得到研究问题后再针对所需字段深查。记录字段含义、单位、周期、特殊缺失、适用人群、连接键、权重或随访结构。不能凭相似名称认定字段等价。
4. 接手已有项目时，盘点真实文件和正式入口，区分“文件存在”“代码可重跑”“结果已核对”“使用者已确认”。保留旧文件，从使用者指定的步骤接续；缺口需要说明，不编造过去的操作。

## 研究设计

读 [研究问题与文献比较](references/study-design.md)。询问人群、暴露、结局、时间关系和主要目的，检索最相关的 3–5 篇原始研究，比较其变量定义、样本与研究流程，注明检索日期、来源和全文/摘要获取情况。

给使用者提供有依据的流程选项，由其确定研究路线。不得因别人使用某方法、目录有某方法或某结果更显著，就把它列为必做。查不到足够论文或缺少检索能力时，说明缺口并讨论，不声称已完成检索。

采用 [研究方案模板](assets/templates/研究方案.md) 和 [研究进度模板](assets/templates/研究进度.md) 留下决定。研究方案允许修改，但修改需记录理由与受影响步骤。

## 当前步骤

先读 [文件与 R 代码](references/files-and-r.md)，再按当前方法读 [方法讨论要点](references/analysis-decisions.md) 对应小节，不一次加载所有方法。

1. 用直白语言说明本步目的、输入、可选处理、参数及检查方式。对不确定且影响研究的问题立即追问；没有默认插补、默认删缺失或默认分组。讨论缺失处理时，明确提醒并询问是否需要针对该决定的敏感性分析；尚未选方法或建议不插补，也不能省略这项提醒。
2. 记录使用者对**这一具体步骤**的确认及出处。只创建当前步目录，用“编号＋任务名”，顺序随本研究安排。
3. 将实际输入复制到当前步并核对来源与校验值。正式代码从当前目录读取；研究需要的字典或类型说明也随步保存。模型对象使用显式 RDS 等文件交接。
4. 参考 [单步 R 骨架](assets/templates/单步分析.R) 写本步代码。骨架需要改写，不能原样当作完成的分析；辅助检查可复制 [本步工具](assets/templates/本步工具.R) 到本步，避免运行时依赖技能目录。
5. 审查项目/暴露/结局身份、路径、字段、未知状态、连接关系、研究参数与注释的一致性。没有确认的研究参数不能填一个数后执行。
6. 普通步骤在新 R 进程运行；可用 `Rscript --vanilla 运行.R`。高计算量步骤只保存和静态审查，填写 [运行说明](assets/templates/高计算量运行说明.md)，状态为“代码就绪，待决定运行”。
7. 核对结果、保存运行环境和检查记录；打开实际图像或渲染表格查看。无法查看时标记“视觉未核对”，不能说全部通过。
8. 用 [本步说明](assets/templates/本步说明.md) 与 [检查记录](assets/templates/检查记录.md) 汇报目的、样本变化、结果位置、检查及限制，然后等待下一步讨论。

## 保存与复核

默认每步简单平铺：R 代码、完整输入、结果、说明和日志放在一起。少量分支用清晰文件名，复杂分支才建子目录，并明确运行顺序与正式入口。

未经解释的缺失、未测量、不适用、覆盖不明不能当零或阴性。模型失败或无法估计的结果保留失败原因，不以别的方法或别的模型结果填补。图表数值从实际模型/结果对象生成，预览与导出使用同一正式结果。

记录输入和代码的校验值。上游变化时，标记受影响的下游为“需重查”，保留旧结果，不自动覆盖或重跑。每步保留必要输入，但不能把受限数据规则误推广为所有公共数据库规则，也不能以“公开库”为由忽略该数据实际许可。

交接时区分：技能/代码检查、模拟运行通过、真实分析核对、科学解释和使用者验收。没有真实分析证据就不能宣称研究有效或达到发表条件。
